## Purpose

This README documents the code files used to construct the Health Professionals Follow-up Study (HPFS) frailty-index analytic data and run longitudinal analyses of frailty trajectories before and after incident cancer. It explains each source script's purpose and the intended order in which scripts should be run.

This file should be updated whenever a new code file is generated or whenever a code file's role, order, or output changes.

Dataset outputs generated by project code, including `.rds`, `.csv`, and other analytic data files, should be saved to:

`/Users/nemo/Library/CloudStorage/OneDrive-HarvardUniversity/Research/Frailty HPFS/Data`

Visual-data outputs used to create reports should be saved to:

`/Users/nemo/Library/CloudStorage/OneDrive-HarvardUniversity/Research/Frailty HPFS/Results/cancer/data`

Knitted HTML/PDF visual reports should be saved to:

`/Users/nemo/Library/CloudStorage/OneDrive-HarvardUniversity/Research/Frailty HPFS/Results/cancer/visuals`

Each active 4.x GLME run also saves one three-page PDF in that directory,
`4.x_GLME_figures.pdf`, containing the event-study contrasts, event-study
predicted means, and natural-spline trajectory in that order.

Persistent PNG files are not saved. Active analysis scripts save plot-ready CSV/RDS data and return plot objects; active R Markdown files render the visual outputs with `knitr`.

Render the active reports from the project root with:

```r
rmarkdown::render(
  "Code/2_data_analysis/3.1_descriptive_riskset_cohorts.Rmd",
  output_dir = "Results/cancer/visuals"
)
rmarkdown::render(
  "Code/2_data_analysis/3.2_exploratory_pre_design_model_eda.Rmd",

rmarkdown::render(
  "Code/2_data_analysis/4.5_GLME_overall_report.Rmd",

)
```

Rendered `.html` files are analysis outputs and should not be treated as source scripts.

## Active Run Order

### 1. Data Cleaning and Analytic Dataset Construction

Run scripts in `1_data_cleaning` first. These scripts load HPFS source data, construct frailty-index items, reshape the data, perform logical imputation, compute frailty-index versions, merge covariates and cancer records, and generate time variables needed for cancer trajectory analyses.

1. `1_data_cleaning/0_load_main_questionaires.Rmd`
   - Reads HPFS main questionnaire files from raw questionnaire sources.
   - Establishes questionnaire-cycle source data used in later frailty and covariate processing.

2. `1_data_cleaning/0.1_load_long_data_using_hpfs_functions.R`
   - Loads core HPFS longitudinal data through the internal `hpfs` package.
   - Pulls baseline, follow-up, death, race, anthropometric, smoking, physical activity, and other questionnaire-derived datasets.

3. `1_data_cleaning/0.2_load nutrient function.R`
   - Defines the nutrient-loading function used to assemble nutrition variables.
   - Covers total calories, blank FFQ items, alcohol, dietary cholesterol, and saturated fat across available questionnaire cycles.

4. `1_data_cleaning/1_construct new df.R`
   - Builds the initial longitudinal working dataset from HPFS source data.
   - Defines passthrough variables and questionnaire mappings that feed the frailty-item construction workflow.

5. `1_data_cleaning/2_construct FI items.R`
   - Constructs and scores individual frailty-index deficit items across questionnaire cycles.
   - Produces item-level inputs for later naming, reshaping, imputation, and frailty-index computation.

6. `1_data_cleaning/3_rename vars.R`
   - Standardizes frailty-item variable names across cycles.
   - Applies the `fi_` prefix convention and prepares consistent item names for longitudinal processing.

7. `1_data_cleaning/4_wide to long.R`
   - Converts frailty and questionnaire variables from wide cycle-specific format to long person-cycle format.
   - Adds follow-up participation information needed for repeated-measures analyses.

8. `1_data_cleaning/5_logical imputation.R`
   - Applies logical imputation to frailty deficit items.
   - Handles irreversible disease indicators and distinguishes missingness from unasked or inapplicable questionnaire items.

9. `1_data_cleaning/6_compute FI.R`
   - Computes the longitudinal frailty index from imputed frailty deficit items.
   - Uses cycle-specific denominators so unavailable items do not incorrectly penalize participants.

10. `1_data_cleaning/7.1_smoking vars.R`
    - Merges smoking status and pack-year variables into the longitudinal frailty dataset.
    - Performs merge checks for newly added smoking variables.

11. `1_data_cleaning/7.2_nutrient vars.R`
    - Merges nutrient variables into the imputed longitudinal frailty dataset.
    - Adds calories, saturated fat, dietary cholesterol, blank FFQ item count, and alcohol intake.

12. `1_data_cleaning/7.3_cancer records.R`
    - Reads fixed-width HPFS cancer record files.
    - Prepares cancer diagnosis, cancer type, and cancer-death variables for linkage to frailty data.

13. `1_data_cleaning/7_merge covariate.R`
    - Merges external covariates, death data, race, smoking, and other participant-level or cycle-level variables.
    - Produces the main longitudinal frailty-index dataset with covariates and cancer information for analysis.

14. `1_data_cleaning/8_compute FI without cancer.R`
    - Computes a frailty index excluding cancer-related deficit items.
    - This is the preferred frailty-index outcome when cancer is the exposure, because it avoids circularity.
    - Output: `Data/FI_longitudinal_1986_2020_IMPUTED_Cancer.rds` (the canonical cancer analytic dataset carrying raw `cancer_*` fields plus earliest-event classification metadata).

15. `1_data_cleaning/7.4_cancer_subtypes.R`
    - Single source of truth for cancer subgroup classification, aligned with
      `Documents/Methods/Cancer_Classification.md`. Reconstructs the earliest
      dated cancer event from endpoint ICD records, writes canonical
      `cancer_index_dateca` and tied-ICD audit fields, and derives smoking,
      obesity, high-burden, sensitivity, and prostate flags only from cancers
      sharing that earliest date. Later cancers cannot reclassify a participant.
    - Removes the original ad hoc HPFS grouping columns (`cancer_carcin`,
      `cancer_carcinp`, `cancer_cancerp`, `cancer_acan`, `cancer_lal`) so they
      cannot be reused. Raw single-site flags and prostate-stage flags are kept.
    - Runs on the cancer analytic dataset, so it must be executed AFTER step 14
      (`8_compute FI without cancer.R`) and before step 16. Reads and overwrites
      `Data/FI_longitudinal_1986_2020_IMPUTED_Cancer.rds`.
    - Active downstream high-burden, smoking, obesity, survival, overall, IPCW,
      and cancer-free matching analyses must use `cancer_index_dateca` for
      analytic timing and the flags written here instead of re-deriving
      ever-status classifications inline.

16. `1_data_cleaning/9_time variables generation.R`
    - Generates age, questionnaire-cycle, death, and cancer-timing variables.
    - Aligns frailty measurements relative to cancer diagnosis and follow-up time for downstream trajectory models.
    - Saves the trajectory-ready derived dataset as `Data/FI_longitudinal_1986_2020_IMPUTED_Cancer_timevars.rds` rather than overwriting the broader cancer analytic dataset.

17. `1_data_cleaning/10_add_base_nutrient_living.R`
    - Adds baseline cycle-86 nutrition and living arrangement covariates to the canonical cancer analytic dataset.
    - Creates `base_calor`, `base_sat`, `base_diet_chol`, `base_nblnk`, `base_alco`, and `base_living`.
    - Preserves missing baseline nutrition values as `NA` and recodes missing baseline living arrangement to `Missing`.
    - Reads and overwrites `Data/FI_longitudinal_1986_2020_IMPUTED_Cancer.rds`.

### 2. Active Cancer Trajectory Analyses

Run scripts in `2_data_analysis` after the cleaned analytic dataset and time variables are available. These are the currently active analysis scripts. Earlier EDA, stochastic-drawing, multiple-imputation, and deprecated matching workflows numbered before `6` have been moved to `2_data_analysis/old`.

1. `2_data_analysis/1.1_check_timebin_fda_support.R`
    - Pre-model diagnostic script for the planned time-bin GLME event-study and complementary functional data analysis (FDA).
    - Loads the risk-set matched long dataset and evaluates whether 2-year relative-time bins have adequate observed no-cancer FI support for cancer cases and controls.
    - Summarizes cancer-case and control support by relative-time bin, mean/median age within each bin, no-later-FI/death-after-bin indicators, repeated FI measurements per trajectory assignment, relative-time coverage, sparse tails, and missing FI by bin.
    - Uses trajectory assignments rather than only original participant ids because risk-set controls can be reused at different assigned index times.
    - Writes diagnostic CSV tables to `Results/cancer/data`; plot objects remain available for later R Markdown rendering. These outputs should guide whether to keep 2-year bins, widen sparse bins, or restrict FDA to a common relative-time window such as -16 to +16 years.

2. `2_data_analysis/2.0_riskset_matching_functions.R`
    - Shared incidence-density risk-set matching helper used by 2.1-2.5.
    - Builds active-at-index eligibility from participation history and applies
      the identical rule to cases and controls: a latest participated target
      cycle on/before index within the cycle caliper and at least one nonmissing
      pre-index FI. Post-index FI and whole-follow-up span never establish entry.
    - Uses primary `min_visits = 1`, seed `20260703`, and up to 1:5 matching with
      replacement across risk sets. It retains every eligible analytic-cycle FI
      row and adds ±8/±12/±16/±20 support flags without a relative-time filter.
    - Adds design metadata including `trajectory_id`, `index_cycle`,
      `index_cycle_rule`, `riskset_size`, `age_gap`, `cycle_gap`, and
      `post_own_cancer`; case-based index-age scaling constants, set-integrity,
      caliper, balance, visit-support, run-configuration, and input-hash metadata;
      writes matching diagnostic CSVs under
      `Results/cancer/data/matching_diagnostics` when cohort builders save outputs.
    - Assigns case index cycles from the shared 4-year analytic calendar,
      excludes zero-control cases from analytic long files, and writes those
      cases separately as `*_unmatched_cases.csv` diagnostics. Case-level
      matching work is parallelized with deterministic per-case tie-breaking.
    - Reads canonical `cancer_index_dateca` for analytic timing and control
      cancer-free eligibility, and rejects nonconstant subgroup flags within
      participant rather than reconstructing ever-status from later rows.
    - `build_riskset_matched_long()` no longer accepts `window_yrs`; wrappers
      2.1–2.5 use the shared unrestricted-row interface. This file is sourced by
      the cohort builders and is not intended to be run directly.

3. `2_data_analysis/2.1_create_riskset_high_low_burden.R`
    - Creates and overwrites `Data/riskset_matched_analysis_long.rds`.
    - Also creates `Data/riskset_matched_analysis_exact_cycle_long.rds` for the
      exact-cycle S7 rematch, reusing the primary case-based index-age scaling.
    - Also creates `Data/riskset_matched_analysis_exact_cycle_long.rds` for
      exact-cycle sensitivity S7, reusing the primary case-based age scale.
    - Uses the canonical `is_high_burden` flag from `7.4_cancer_subtypes.R` to
      build Low/Moderate Burden and High Burden cohorts, each with separately
      matched risk-set controls using the shared 2.0 design settings.

4. `2_data_analysis/2.2_create_riskset_smoking_related.R`
    - Creates and overwrites `Data/riskset_matched_smoking_long.rds`.
    - Also creates `Data/riskset_matched_smoking_exact_cycle_long.rds` for the
      exact-cycle S7 rematch, reusing the primary case-based index-age scaling.
    - Also creates `Data/riskset_matched_smoking_exact_cycle_long.rds` for
      exact-cycle sensitivity S7, reusing the primary case-based age scale.
    - Uses the canonical `is_smoking_cancer` flag from `7.4_cancer_subtypes.R`
      to build a Smoking-Related Cancer Cohort versus cancer-free controls
      using the shared 2.0 design settings.

5. `2_data_analysis/2.3_create_riskset_obesity_related.R`
    - Creates and overwrites `Data/riskset_matched_obesity_long.rds`.
    - Also creates `Data/riskset_matched_obesity_exact_cycle_long.rds` for the
      exact-cycle S7 rematch, reusing the primary case-based index-age scaling.
    - Also creates `Data/riskset_matched_obesity_exact_cycle_long.rds` for
      exact-cycle sensitivity S7, reusing the primary case-based age scale.
    - Uses the canonical `is_obesity_cancer` flag from `7.4_cancer_subtypes.R`

      using the shared 2.0 design settings.

6. `2_data_analysis/2.4_create_riskset_survival.R`
    - Creates and overwrites `Data/riskset_matched_survival_long.rds`.
    - Also creates `Data/riskset_matched_survival_exact_cycle_long.rds` for the
      exact-cycle S7 rematch, reusing the primary case-based index-age scaling.
    - Also creates `Data/riskset_matched_survival_exact_cycle_long.rds` for

    - Builds Died <=5y and Survived >5y cohorts among incident cancer cases.

7. `2_data_analysis/2.5_create_riskset_overall.R`
    - Creates and overwrites `Data/riskset_matched_overall_long.rds`.
    - Pools all incident (first) cancer cases into a single "All Cancer Cohort"

10. `2_data_analysis/4.0_GLME_spline_functions.R`
    - Shared engine for the time-bin GLME event-study analysis and the
      natural-spline Gaussian LME model set, used by 4.1-4.5. Methods documented in
      `Documents/Methods/TimeBin_GLME_EventStudy_Analysis.md` and
      `Documents/Methods/GLME_Natural_Spline_Trajectory_Analysis.md`.
    - Per cohort: cuts relative time into the 2-year event-study bins from `1.1`
      (reference = last pre-index bin `-2 to 0`); fits the saturated
      `Group * rel_time_bin` GLME with a random intercept; attempts CR2
      cluster-robust SEs on participant `id` and falls back to CR0 or model-based
      inference when necessary (control reuse makes `id` non-nested within
      `match_set`); runs
      global/pre-index/post-index joint Wald tests; and fits M0 raw df-3 spline,
      M1 primary df-3 spline, M2 full df-3 spline, and M3 matching-set df-3
      spline models from the GLME methods file. The models fit all eligible matched long rows
      and restrict predictions/contrasts/plots to the ±20 support window. S3
      and S4 retain ±8 and ±12 support windows.
    - Writes event-study outputs plus spline fixed-effect CIs, predicted
      trajectories, cancer-minus-control difference curves, theta summaries,
      and model-status tables. Each run also saves one three-page
      `4.x_GLME_figures.pdf` to `Results/cancer/visuals`; no PNG files are saved.
    - Before every primary fit, excludes `post_own_cancer` control rows at or
      after the control's own later cancer diagnosis, while preserving the
      pre-diagnosis assignment history and requiring a current matched dataset.
    - Separates event-study support-qualified bins from the all-eligible model
      fitting data; centers/scales model-specific spline columns (and M2's
      continuous dietary covariates), replays those
      stored transformations for every prediction/contrast grid, and writes
      support, complete-case-filter, own-cancer-censoring, derivative,
      spline-scaling, and spline-basis metadata artifacts. Covariance uses the
      explicit CR2 -> CR0 -> model-based fallback (with M3 retained when robust
      covariance is unavailable). Adjusted prediction grids use the most common
      factor level among distinct participants in each model-specific complete-
      case sample, rather than an arbitrary first factor level; prediction is
      restricted to a continuous two-arm support window. Every subgroup fit
      first validates Gate G4 and the matched-RDS input hash.
    - This file is sourced by 4.1-4.5 and is not intended to be run directly.

16. `2_data_analysis/5.0_fda_functions.R`
    - Shared functional data analysis (FDA) helper. Converts a risk-set matched
      long dataset (2.1-2.5) into the sparse functional-data format required by
      `fdapace` (PACE / sparse FPCA): `Ly` (FI value vectors) and `Lt`
      (relative-time vectors), one curve per trajectory assignment
      (`Cohort__match_set__id__role`), plus an aligned `meta` table. Optionally
      runs sparse FPCA and a Cancer-vs-Control mean-function comparison.
    - Sparse FPCA is used because HPFS FI is measured on a few irregular cycles
      per person with person-specific relative time, so no common grid exists; no
      binning/interpolation is fabricated. Sourced by 5.1+, not run directly.

17. `2_data_analysis/5.1_fda_overall.R`
    - Loads `Data/riskset_matched_overall_long.rds` generated by 2.5, converts it

      and runs sparse FPCA with a Cancer-vs-Control mean-function comparison.
    - Writes `5.1_fpca_scores.csv`, `5.1_fpca_eigenfunctions.csv`, and
      `5.1_fpca_mean_by_group.csv` to `Results/cancer/data`. The same functions
      apply to any 2.x matched dataset by changing the input path.
    - Existing overall FDA products become stale when 2.5 overwrites the matched
      RDS and must not be compared with the repaired GLME until FDA is rebuilt.

18. `2_data_analysis/7.0_ipcw_functions.R`
    - Shared inverse-probability-of-censoring-weighting (IPCW) engine for the
      observation (questionnaire-response) process. Fits stabilized pooled
      logistic models for remaining observed given still alive, among person-
      cycles at risk (alive and observed at the prior analytic cycle), then forms
      cumulative stabilized weights and attaches post-index conditional `sw_ipcw`
      to a matched dataset. Documented in
      `Documents/Methods/IPCW_Censoring_Weights.md`.
    - Predictors (all lagged): prior FI + baseline FI, time-varying cancer status
      and years since diagnosis, age spline, cycle, response history, and the
      section-10 covariates `race`, `marital_status`, `living_arr`, `smoke`,
      `pckyr`, `bmi`, `act`, `alco`. Time-varying comorbidity items are excluded;
      death is NOT weighted away (left to the estimand). Sourced by 7.1+.

19. `2_data_analysis/7.1_ipcw_overall.R`
    - Builds IPCW for the overall any-cancer-vs-control comparison from the
      longitudinal panel and the 2.5 matched dataset, writing
      `Data/riskset_matched_overall_long_ipcw.rds` (matched long + `sw_ipcw`) and
      `7.1_ipcw_weight_*` diagnostics to `Results/cancer/data`. The event-study (4.5)
      and spline GLME models can then be re-fit with `weights = sw_ipcw`. The
      same functions apply to any 2.x dataset by changing the paths. Existing
      overall IPCW datasets and model outputs become stale after a 2.5 rebuild;
      they are not rebuilt as part of the overall matching/GLME repair.

20. `2_data_analysis/7.2_ipcw_glme_spline_overall.R`
    - Loads `Data/riskset_matched_overall_long_ipcw.rds` generated by 7.1 and
      fits the IPCW-weighted overall natural-spline GLME:
      `Group * ns(Age_Centered, df = 4)` plus index-age, race, marital-status,
      and pack-year adjustment, with random intercept and relative-time slope by
      participant id.
    - Writes weighted fixed-effect CIs, predicted case/control trajectories, the
      smooth cancer-minus-control difference curve, figures, and the fitted model
      object to `Results/cancer/data` using the `7.2_ipcw_glme_spline_*` prefix.
    - This is the weighted downstream GLME spline analysis for the overall cancer
      cohort after IPCW construction; it does not create or overwrite matched
      datasets.

21. `2_data_analysis/7.3_ipcw_subtype_cohorts.R`
    - Builds one shared stabilized IPCW object from the longitudinal panel and
      attaches post-index conditional `sw_ipcw` to the active non-prostate cancer
      subtype matched datasets from 2.1-2.3: high/low burden, smoking-related,
      and obesity-related cohorts.
    - Writes `Data/riskset_matched_analysis_long_ipcw.rds`,
      `Data/riskset_matched_smoking_long_ipcw.rds`, and
      `Data/riskset_matched_obesity_long_ipcw.rds`, plus `7.3_*_ipcw_weight_*`
      diagnostics to `Results/cancer/data`.
    - Prostate subtype cohorts are deliberately excluded; survival-stratified
      cohorts are also excluded here because they classify cases by a post-index
      survival/prognosis outcome rather than cancer subtype.

22. `2_data_analysis/7.4_ipcw_glme_spline_subtype_cohorts.R`
    - Loads the IPCW-augmented subtype datasets generated by 7.3 and fits
      separate IPCW-weighted natural-spline GLMEs within each active subtype
      cohort: Low/Moderate Burden, High Burden, Smoking-Related Cancer,
      and Obesity-Related Cancer.
    - Uses `Group * ns(Age_Centered, df = 4)` plus index-age, race,
      marital-status, and pack-year adjustment, with random intercept and
      relative-time slope by participant id and `weights = sw_ipcw`.
    - Writes weighted fixed-effect CIs, predicted case/control trajectories, the
      smooth cancer-minus-control difference curves, figures, and fitted model
      objects to `Results/cancer/data` using the
      `7.4_ipcw_glme_spline_subtypes_*` prefix.

23. `2_data_analysis/7.5_compare_ipcw_vs_unweighted_spline.R`
    - Compares the saved unweighted natural-spline GLME outputs from 4.1-4.5
      against the IPCW-weighted natural-spline GLME outputs from 7.2 and 7.4
      using the same cohort definitions.
    - Produces full-grid and selected-key-time comparisons for cancer-case
      predicted FI and cancer-minus-control spline contrasts. Key times are
      -16, -12, -8, -4, 0, +4, +8, +12, and +16 years relative to index.
    - Writes `7.5_ipcw_vs_unweighted_*` CSV comparison tables to
      `Results/cancer/data`; plot objects are retained for later R Markdown
      rendering. Unweighted cancer-minus-control contrast CIs are not
      reconstructed because 4.x did not save the spline model covariance.

24. `2_data_analysis/8.1_joint_model_overall.R`
    - Builds the overall cancer joint-modeling datasets and fits a mortality-
      informative joint model linking the same natural-spline FI trajectory
      specification used in 7.2 to time from assigned index to all-cause death.
    - The longitudinal submodel uses `nlme::lme` with
      `Group * ns(Age_Centered, df = 4)` plus index-age, race, marital-status,
      and pack-year adjustment, with random intercept and relative-time slope by
      trajectory assignment (`Cohort__match_set__id__role`) so reused controls at
      different assigned index times remain distinct.
    - The survival submodel uses `survival::coxph` for death after assigned index
      time, censored at the fixed 2020 analytic-cycle date. `JMbayes2::jm` links
      the Cox model to the latent current-value frailty trajectory.
    - Writes the longitudinal and survival analysis datasets, survival summary,
      model summaries, predicted longitudinal trajectories, a joint-model
      diagnostic, and fitted model object to `Results/cancer/data` using the
      `8.1_joint_model_overall_*` prefix. `JMbayes2` is required and the script
      always attempts the linked Bayesian joint model after saving the formulated
      datasets and component submodels; if the full fit exceeds local runtime or
      memory, the limitation is recorded in the diagnostic file.
    - Existing overall joint-model products become stale after the corrected
      matched RDS and canonical GLME metadata are regenerated; do not interpret
      them until the joint-model prerequisites are intentionally rebuilt.
